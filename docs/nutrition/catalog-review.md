# بازبینی و انتشار مرحله‌ای کاتالوگ

## فهرست داده‌های ناقص

یک خروجی JSON خواندنی از جدول `food_items` بگیرید. فیلدهای لازم `id`، `is_active`، `allergy_flags`، `allergen_assessment`، `allergen_assessment_source`، `recipe_reference_version`، `recipe_batch_yield_grams` و `recipe_batch_servings` هستند.

```bash
npm run --silent review:nutrition-catalog -- --catalog foods.json > catalog-gaps.json
```

گزارش برای غذاهای فعال، آلرژن‌های فاقد ارزیابی ثبت‌شده و وضعیت مرجع و بازده بچ را نشان می‌دهد. برای غذای ساده، نبود بازده بچ می‌تواند طبیعی باشد. وضعیت‌های موجود از همان خروجی خوانده می‌شوند. گزارش کیفیت یا اعتبار شواهد را داوری نمی‌کند.

## پروندهٔ بازبینی هر دستور جدید

برای نسخهٔ مشخصی از یک دستور ایرانی، فایل JSON را با فیلدهای زیر آماده کنید. هر شیء منبع شامل `name`، `url` با HTTPS و `locator` برای مکان دقیق داده در سند است. گزارش یا اندازه‌گیری داخلی نیز می‌تواند در نشانی امن و قابل دسترسی برای بازبین نگهداری شود.

| فیلد | داده |
|---|---|
| `schemaVersion`، `id`، `version`، `name` | نسخهٔ قالب برابر ۱، شناسه و نسخهٔ پایدار و نام غذا |
| `source` | منبع خود دستور |
| `gramsPerUnit`، `preparationState` | وزن واحد مرجع و وضعیت `cooked` برای این مسیر بازبینی |
| `ingredients` | فهرست مواد در بچ، با `name`، `grams` و `preparationState` خام، خشک، پخته یا آماده با مقادیر `raw`، `dry`، `cooked` و `ready` |
| `batch` | `cookedGrams` برای وزن کل بچ آماده، `servings` برای تعداد سهم منبع، `method` برابر `measured` یا `published` و `source` برای شواهد بازده |
| `nutrition` | `kcal`، `proteinGrams`، `carbGrams`، `fatGrams`، `fiberGrams` بر مبنای همان واحد پخته، با `source` |
| `allergens` | برای هر ۹ کلید `dairy`، `gluten`، `peanut`، `tree_nut`، `soy`، `seafood`، `celery`، `egg` و `sesame`، وضعیت `ingredients` و `crossContact` با `ingredientSource` و `crossContactSource` |
| `micronutrients` | `calcium`، `iron`، `sodium`، `potassium` با واحد `mg` و `vitamin_d` با واحد `µg`. مقدار ثبت‌شده به‌صورت `{ amount, unit, source }` و دادهٔ نامعلوم به‌صورت `null` |

`ingredients` داخل هر ارزیابی آلرژن می‌تواند `contains`، `absent` یا `unknown` باشد. برای `crossContact` از `possible`، `controlled` یا `unknown` استفاده کنید. ثبت نبود آلرژن به شواهد بررسی مواد و کنترل تماس متقاطع نیاز دارد. مقدار صفر ریزمغذی نیز به منبع نیاز دارد. وزن واحد مرجع و تعداد سهم منبع را جدا ثبت کنید. متخصص مبنای وزن و محاسبهٔ مواد مغذی را با مدارک تطبیق می‌دهد.

```bash
npm run --silent review:nutrition-catalog -- --candidate recipe.json
npm run --silent review:nutrition-catalog -- --candidate recipe.json --approval approval.json
```

گزارش اول موارد ناقص یا `awaiting_review` را نشان می‌دهد. متخصص پس از بررسی دستور، برچسب مواد، شرایط تهیه، وزن پخته و اعداد، یک تصمیم مستند ثبت می‌کند. فایل تصمیم شامل `fingerprint` از گزارش، `reviewer`، `decisionRef` برای شناسهٔ تصمیم، `date` به قالب `YYYY-MM-DD` و `decision` برابر `approved_for_pilot` است. تغییر دادهٔ نسخه، تصمیم قبلی را نامعتبر می‌کند. وضعیت `review_recorded` یعنی فایل تصمیم با نسخهٔ بررسی‌شده تطبیق دارد. اصالت و صلاحیت تأییدکننده را در رکورد تصمیم تیم بررسی کنید.

## انتشار

1. پروندهٔ دستور و تصمیم را کنار هم بایگانی کنید. ابتدا یک دستور را در محیط آزمایشی به کاتالوگ موجود اضافه کنید. واحد، وضعیت پخت، ارزیابی آلرژن و منشأ را با گزارش مطابقت دهید.
2. تولید عضو و پرو، جایگزینی، محدودیت غذایی و PDF فارسی را با همان نسخه بررسی کنید. ریزمغذی‌های این پرونده در مرحلهٔ حاضر برای بازبینی داده ثبت می‌شوند. محاسبه و نمایش آن‌ها در اپ به قرارداد مستقل نیاز دارد.
3. بعد از تأیید، همان نسخه را در انتشار محدود قرار دهید. برای توقف، پیشنهادشدن نسخه در برنامه‌های تازه را متوقف کنید و snapshot برنامه‌های ذخیره‌شده و سابقهٔ تصمیم را نگه دارید.

بازبینی منحنی پروتئین مسیر مستقلی دارد. برای متخصص، مقایسهٔ سیاست فعلی و پیوسته را با [گزارش نسخه‌دار E07](engine-status.md#بازبینی-سیاست-پروتئین-در-e07) تولید کنید. تأیید متخصص باید به نسخهٔ سیاست، گزارش و جمعیت مورد بررسی ارجاع بدهد. ابزار بازبینی کاتالوگ آفلاین است و تنظیمات انتشار یا سیاست پروتئین را تغییر نمی‌دهد.
