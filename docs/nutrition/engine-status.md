## بازبینی سیاست پروتئین در E07

دستورهای زیر فقط محاسبهٔ محلی روی پرونده‌های مصنوعی انجام می‌دهند. در حالت پیش‌فرض، سیاست مبنا از کد مخزن خوانده می‌شود. برای مقایسه با سیاست جاری محیط مقصد، یک ردیف معتبر از `nutrition_protein_policy` را به‌شکل یک شیء JSON به `--baseline` بدهید. `--candidate` همان قالب را برای سیاست پیشنهادی می‌گیرد.

```bash
npm run --silent review:protein-policy > baseline-review.json
npm run --silent review:protein-policy -- --baseline policy-current.json --candidate policy-proposed.json > comparison-review.json
npm run --silent review:protein-policy -- --continuous > continuous-review.json
```

گزارش ضرایب، شناسه، زمان نسخه و اثر انگشت سیاست را همراه با وزن مرجع، انرژی، درشت‌مغذی‌ها و وضعیت سقف‌های پروتئین ثبت می‌کند. هر دو سیاست در وزن‌های یکسان در دو طرف مرزهای BMI مقایسه می‌شوند. برای مثال، خروجی مبنای مخزن در پروندهٔ مصنوعی با قد ۱۷۸ سانتی‌متر برای ۹۵ و ۹۵٫۱ کیلوگرم به‌ترتیب ۱۹۰ و ۱۷۱ گرم است.

سقف سهم انرژی و سقف گرم پروتئین روی خروجی نهایی به گرمِ کامل اعمال می‌شوند. گزارش سقفی را فعال علامت می‌زند که مقدار خروجی را کاهش داده است. اگر هر دو سقف به همان مقدار نهایی برسند، هر دو فعال‌اند.

با `--continuous` می‌توان خود منحنی را با همان ضرایب مبنا مقایسه کرد. این پیشنهاد مقدار وزن مرجع را پیش از مرز BMI به سطح شاخهٔ تعدیل‌شده در خود مرز محدود می‌کند. نتیجه بازه‌ای با وزن مرجع ثابت است که در دو سر پیوسته است. در مثال بالا، هدف پیشنهادی در هر دو وزن ۱۷۱ گرم می‌شود. اثر اصلی در بخش پایین مرز است و لازم است متخصص کاهش هدف را در آن بازه بررسی کند.

اجرای آزمون درون مخزن با `npm run test:protein-policy` انجام می‌شود. برای تصمیم انتشار، نسخهٔ سیاست فعلی و پیشنهادی را کنار گزارش نگه دارید و گروه‌های مشمول، اندازهٔ افت پیش از مرز، اثر روی کربوهیدرات و سقف‌های پروتئین را با متخصص مرور کنید.

### انتشار و بازگشت E07

ابتدا کد عضو، پرو و سرور را منتشر کنید و مایگریشن [۰۵۸](../../supabase/migrations/20261115234234_058_protein_reference_weight_model.sql) را اعمال کنید. مقدار اولیهٔ `reference_weight_model` برابر `step-v1` است. نسخهٔ مدل از همان snapshot کاتالوگ و سیاست به عضو و پرو می‌رسد. تغییر نسخه، revision کاتالوگ را جلو می‌برد. برنامه‌های جدید عضو نسخهٔ مدل را در snapshot و پیش‌نویس‌های جدید پرو در trace ثبت می‌کنند.

پس از ثبت تأیید متخصص، برای فعال‌سازی در محیط مقصد از حساب مدیریتی دیتابیس استفاده کنید.

```sql
update public.nutrition_protein_policy
set reference_weight_model = 'continuous-lower-envelope-v1'
where id = 'default' and reference_weight_model = 'step-v1'
returning id, reference_weight_model, updated_at;
```

پس از فعال‌سازی، در نشست تازه و با پروندهٔ مصنوعی هر دو مسیر عضو و پرو را بررسی کنید. تصمیم بازگشت را هم با نسخهٔ سیاست ثبت کنید. برای بازگشت، پیش از برگرداندن کد، مدل را به مقدار قبل برگردانید.

```sql
update public.nutrition_protein_policy
set reference_weight_model = 'step-v1'
where id = 'default' and reference_weight_model = 'continuous-lower-envelope-v1'
returning id, reference_weight_model, updated_at;
```

هر تغییر یک revision تازه ایجاد می‌کند. آرشیوها و پیش‌نویس‌های ذخیره‌شده از همان snapshot قبلی خوانده می‌شوند. برنامه‌های عضو در اولین تولید با snapshot جدید به‌روز می‌شوند و سوابق مصرف مستقل می‌مانند.

منابع بازبینی از وزن مرجع و وزن تعدیل‌شده در زمینه‌های بالینی مشخص بحث می‌کنند. انتخاب وزن مبنا به جمعیت و هدف درمان وابسته است. مستند تصمیم متخصص باید دامنهٔ استفاده را روشن کند.
