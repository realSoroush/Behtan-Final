# انتقال برنامهٔ عضو به API نسخه‌دار

> وضعیت جدید E02/E03، ترتیب دو مرحله‌ای 051 و 052 و جدول ۱۸ تسک در [ثبت اتمیک مصرف عضو](member-intake-transactions.md) است. جزئیات مراحل قدیمی زیر برای سابقه حفظ شده‌اند.


پایهٔ شاخه کامیت `07359e9` از `main` است. تغییرهای 048 و 049 در آن ادغام شده‌اند. مهاجرت 050 باید پیش از انتشار کد این PR روی دیتابیس متصل به نسخهٔ جدید اعمال شود.

## رفتار قابل بررسی

- رابط عضو برای ساخت برنامه، تغییر وعده، جایگزینی و تغییر روز تمرین فقط قصد تغییر و نسخه‌ها را به `/api/member` می‌فرستد. برنامهٔ هفته روزبه‌روز ذخیره می‌شود. روزهای ذخیره‌شده هنگام خطای یکی از روزها باقی می‌مانند.
- برنامه، ثبت مصرف، وعدهٔ نخورده و غذای اضافهٔ امروز از یک snapshot خوانده می‌شوند. بازگشت به صفحه و تغییر اتصال خواندن تازه را آغاز می‌کنند. اعتبار پیش‌نمایش به نسخهٔ برنامه و ثبت‌های همان روز وابسته است.
- در صورت گم‌شدن پاسخ، درخواست با همان شناسه و محتوا تکرار می‌شود. پس از تأیید، وضعیت تازه از سرور خوانده می‌شود. تعارض نسخه با پیام بازیابی نشان داده می‌شود.
- پیشنهاد قدیمیِ سازگار قابل نمایش و ثبت مصرف است. برای تغییر پیشنهاد یا جایگزینی، دکمهٔ به‌روزرسانی یک برنامهٔ معتبر سمت سرور می‌سازد. ممکن است ترکیب پیشنهادی تغییر کند. ثبت‌های مصرف مستقل می‌مانند.
- 050 شناسهٔ غذای اضافه و نسخهٔ کاتالوگ را به snapshot اضافه می‌کند. بودجهٔ ساخت یا تغییر برنامه ۱۲ درخواست در دقیقه برای هر حساب است. بودجهٔ پرداخت و تمرین همچنان ۵ درخواست در دقیقه برای هر مسیر است.

## ترتیب انتشار

1. در Checks همین PR، اجرای مرورگر و PostgreSQL واقعی را بررسی کن. ابتدا 050 و کد شاخه را روی محیط آزمایشی با حساب آزمایشی دارای اشتراک امتحان کن.
2. در PowerShell داخل `E:\Behtan-Final` یک پوشهٔ جدا از شاخهٔ PR بگیر و فایل را به سرور منتقل کن. Docker روی PC لازم نیست.

```powershell
Set-Location E:\Behtan-Final
git fetch origin
git worktree add --detach ..\Behtan-Meal-Cutover origin/fix/member-meal-cutover
scp ..\Behtan-Meal-Cutover\supabase\migrations\20261105213810_050_member_meal_cutover.sql root@95.38.186.191:/opt/behtan/migration/
```

3. در نشست SSH سرور ایران، پس از تأیید انتشار، بکاپ را بگیر و migration را اعمال کن. خروجی باید با `COMMIT` تمام شود.

```bash
cd /opt/behtan/supabase
(
  set -eu
  umask 077
  backup=$(mktemp /opt/behtan/migration/pre-050-XXXXXX.dump)
  docker compose exec -T db pg_dump -U postgres -d postgres -Fc > "$backup"
  docker compose exec -T db pg_restore -l < "$backup" > /dev/null
  docker compose exec -T db psql -U postgres -d postgres -v ON_ERROR_STOP=1 \
    < /opt/behtan/migration/20261105213810_050_member_meal_cutover.sql
)
```

4. در Vercel، پروژهٔ `behtan-final`، بخش **Settings → Environment Variables** را در محیط هدف بررسی کن. `VITE_SUPABASE_URL`، `VITE_SUPABASE_ANON_KEY` و `SUPABASE_SERVICE_ROLE_KEY` باید متعلق به همان دیتابیس باشند و `MEMBER_RELEASE_ENABLED` مقدار `true` داشته باشد. سپس PR را ادغام کن و منتظر وضعیت Ready بمان.
5. با یک حساب آزمایشی روی دو مرورگر وارد شو. تغییر وعده و جایگزینی را انجام بده و پس از refresh و بازکردن دستگاه دوم بررسی کن. در مرورگر اول یک جایگزین را پیش‌نمایش کن. در مرورگر دوم وعده‌ای را ثبت کن. تأیید پیش‌نمایش قدیمی باید تعارض بدهد و پس از دریافت نسخهٔ تازه قابل تکرار باشد. ساخت هفته، تغییر روز تمرین، undo، نخوردم و غذای اضافه را هم بررسی کن. برای پرداخت، نمایش قیمت و preflight را با حساب آزمایشی بررسی کن.
6. در صورت برگشت، دیپلوی قبلی Vercel را بازگردان و migration 050 را نگه دار. مسیر قدیمی هنوز قابل استفاده است. جدول‌ها و داده‌های ثبت‌شده را برنگردان.
