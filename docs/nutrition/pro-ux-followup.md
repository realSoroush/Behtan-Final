# تکمیل اصلاحات پرو پس از PR45

مبنا: `main@1d40a0b`، پس از ادغام PR45. نصب و تست مایگریشن‌های 053 و 054 توسط کاربر اعلام شده است. این بسته مایگریشن تازه ندارد و این دو فایل نباید برای نصب آن دوباره اجرا شوند.

## اصلاح‌های تأییدشده

- در آرشیو انتهای پرونده، مشاهدهٔ برنامهٔ تغذیه فقط `section.lines` را نمایش می‌داد و منوهای جایگزین را پنهان می‌کرد. اکنون همان جدول منوهای استودیو، همراه نوع روز، مقدار مواد و درشت‌مغذی‌ها نمایش داده می‌شود. محتوای ذخیره‌شده و محاسبات آن بازنویسی نمی‌شوند؛ برنامه‌های تمرینی و متن‌های قدیمی همچنان خوانده می‌شوند.
- فرم حرکت اختصاصی مربی، هنگام انتخاب حرکت دیگر می‌توانست state حرکت قبلی را حفظ کند. فرم اکنون با شناسه و revision حرکت انتخاب‌شده از نو ساخته می‌شود؛ ذخیره به همان شناسه و نسخه مربوط است.
- عنوان و یادداشت نسخهٔ تغذیه در مشاهدهٔ سوابق، دوبار نمایش داده نمی‌شوند.
- در منوی صرفاً متنی قدیمی، مقدار نامعلوم به‌صورت «۰ کالری» نشان داده نمی‌شود. نمایش سوابق و PDF از توضیح مشترک استفاده می‌کنند: نبود مقدار با «مقادیر تغذیه‌ای ثبت نشده‌اند» مشخص می‌شود و جمع منوی دارای مواد معلوم و سطر متنی، صریحاً جمع جزئی است. صفر واقعیِ ثبت‌شده همچنان صفر نمایش داده می‌شود.

هر دو ایراد اصلی با تست رندر روی کد مبنا بازتولید شدند؛ همان تست‌ها پس از اصلاح پاس شدند. تست مرورگر نیز آرشیو چندمنویی و انتخاب/ویرایش دو حرکت اختصاصی را روی دسکتاپ و موبایل پوشش می‌دهد. نتیجهٔ نهایی CI در PR ثبت می‌شود. این شواهد معادل تست production یا بازبینی علمی حرکات نیستند.

## ترتیب اعمال

1. PR و Checks آخرین کامیت را بررسی کنید. در Preview، سناریوهای زیر را امتحان کنید.
2. خودتان PR را Merge کنید و منتظر Ready انتشار Pro در Vercel بمانید. متغیر محیطی، SQL یا انتشار Edge Function تازه لازم نیست.
3. برای همگام‌کردن پروژهٔ PC، در **Windows PowerShell** اجرا کنید:

```powershell
Set-Location E:\Behtan-Final
git status
git fetch origin
git switch main
git pull --ff-only origin main
```

اگر `git status` تغییر محلی نشان داد، آن را حذف یا بازنویسی نکنید؛ پیش از تغییر شاخه، همان تغییرات را نگه دارید. اگر `pull --ff-only` خطا داد، از reset یا force استفاده نکنید.

**سرور ایران و Supabase Studio:** برای این بسته دستوری لازم نیست. مایگریشن‌های قبلی و داده‌های آن‌ها حفظ شوند.

## بررسی پس از انتشار

- یک برنامهٔ تغذیه با حداقل دو منوی متفاوت در یک وعده ذخیره کنید. پنجرهٔ استودیو را ببندید و از آرشیو انتهای پرونده «مشاهده برنامه اختصاصی» را بزنید؛ هر دو منو و مقدارهایشان باید دیده شوند. PDF، مشاهدهٔ داخل استودیو و آرشیو باید همان منوها را نشان دهند. یک نسخهٔ تمرینی قدیمی را نیز باز کنید.
- دو حرکت اختصاصی مربی با نام‌های متفاوت داشته باشید. اول الف و سپس ب را انتخاب کنید؛ ورودی‌های ویرایش باید ب را نشان دهند. فقط ب را ویرایش و ذخیره کنید؛ پس از دریافت دوبارهٔ بانک، الف باید بدون تغییر مانده باشد.
- عنوان و یادداشت نسخه در سوابق فقط یک‌بار نمایش داده شوند؛ نمایش موبایل اسکرول افقی اضافه نداشته باشد.

## بازگشت

در صورت رگرسیون، انتشار کد Pro را به نسخهٔ PR45 برگردانید. هیچ جدول، حرکت، برنامه یا audit را حذف نکنید. این بسته شکل ذخیره‌سازی و قرارداد RPC را تغییر نمی‌دهد؛ بازگشت کد به rollback دیتابیس نیاز ندارد.

موج‌های بعدی سند E01 تا E18 در این بسته شروع نشده‌اند.
