# انتشار اصلاحات UX پنل پرو

مبنای این بسته `main@6fc2aca`، پس از PR44 است. موج‌های بعدی سند موتور تغذیه همچنان متوقف‌اند؛ این بسته پنج مورد درخواست‌شدهٔ پنل پرو و ادمین را پوشش می‌دهد.

## رفتار جدید

1. **حرکات اصلاحی:** ۱۲۰ ردیف سند به ۱۱۷ رکورد یکتا در ده دسته تبدیل شده‌اند. موارد مشترک Wall Slide، Lateral Band Walk و Single Leg Balance / Stance یک شناسه و چند دسته/نام جایگزین دارند. شناسه‌ها مستقل از نام‌اند. بانک از دیتابیس خوانده می‌شود؛ فیلترهای هم‌زمان، نام فارسی/انگلیسی/مترادف، جزئیات و رسانه، حرکت اختصاصی فضای کاری و آرشیو پشتیبانی می‌شوند. حرکات بانک وارد تولید خودکار تمرین نمی‌شوند.
2. **تعداد منوی خودکار:** رابط، API و validator دیتابیس تا پنج منو را می‌پذیرند. انتخاب منوها به‌صورت گروه‌های وعده در سطح روز حل می‌شود؛ افزودن حریصانه به هر وعده می‌توانست ظرفیت انتخاب وعده‌های بعد را کم کند. غذاهای جایگزین فقط از ارتباط‌ها و قواعد فعلی کاتالوگ می‌آیند و سهم‌ها با solver موجود دوباره حل می‌شوند. کنترل آلرژی، سهم، اندازهٔ وعده، دستورهای دارای سهم ثابت و کران تمام ترکیب‌های مستقل روز حفظ شده است. ضرایب تغذیه تغییر نکرده‌اند.
3. **خروجی دقیق:** سند جدید `menu_contract=exact-v2` دارد و هر وعدهٔ خروجی موفق دقیقاً تعداد انتخاب‌شده را دارد. منوی یکسان با نام جدید یا با تغییر جزئی گرم، گزینهٔ متمایز محسوب نمی‌شود. اگر جست‌وجوی محدود نتواند به تعداد لازم برسد، `PRO_MENU_COUNT_UNAVAILABLE` می‌دهد و خروجی کمتر ذخیره نمی‌شود. این خطا اثبات ناممکن‌بودن بالینی نیست. در بعضی رژیم‌ها، اهداف کم‌کالری یا روزهای تمرین با گزینه‌های محدود پس از تمرین، چهار یا پنج ترکیب مستقلِ متمایز با کاتالوگ فعلی پیدا نمی‌شود؛ کاهش تعداد یا دادهٔ معتبر بیشتر لازم است. گزینهٔ نامعتبر برای پرکردن عدد اضافه نمی‌شود.
4. **استودیوی تغذیه:** هر وعده یک منوی اول و حداکثر چهار جایگزین دارد. همهٔ گزینه‌های برنامهٔ خودکار به استودیو منتقل می‌شوند. هر منو در یک سطر با مواد، گرم/مبنای وزن، کالری و درشت‌مغذی‌ها نمایش داده می‌شود و جداگانه ویرایش می‌شود. سوابق و PDF نیز همهٔ منوها را نگه می‌دارند. جمع پایه فقط منوهای اول را حساب می‌کند؛ دامنهٔ روز کمینه/بیشینهٔ انتخاب‌هاست، نه جمع همهٔ گزینه‌ها. این نمایش، تأیید خودکار تغذیهٔ اختصاصی متخصص نیست.
5. **آمار و پشتیبانی:** ادمین آمار تجمیعی پرو با بازهٔ شامل تمام روز پایان، به وقت تهران دارد. لینک‌های پشتیبانی پرو به `https://t.me/Behtan_Support` متصل‌اند.

## مرز علمی بانک اصلاحی

سند ورودی نام‌ها و دسته‌ها را پیشنهاد می‌کند و تصریح کرده پیش از انتشار، شرح اجرا و احتیاط هر حرکت باید توسط متخصص واجد صلاحیت بازبینی شود. برای هیچ‌یک از ۱۱۷ ردیف، بازبین، صلاحیت، تاریخ یا منبع علمی تأییدشده جعل نشده است. همهٔ ردیف‌های اولیه **پیش‌نویس** هستند؛ فیلدهای نامعلوم خالی‌اند. برچسب تجهیز فقط در موارد صریح نام حرکت وارد شده و این طبقه‌بندی نیز پیش‌نویس است.

در Pro، پیش‌نویس می‌تواند پس از تأیید مسئولیت انتخاب توسط متخصص، به‌عنوان تدوین اختصاصی او وارد برنامه شود؛ این به معنی انتشار علمی بانک نیست. ست/تکرار/زمان/استراحت آن پیش‌فرض تأییدشده ندارد و باید تکمیل شود. دوز زمان‌دار علاوه بر تکراری پشتیبانی می‌شود. رکورد آرشیوشده قابل انتخاب تازه نیست و نسخهٔ ذخیره‌شده را تغییر نمی‌دهد. حرکت اختصاصی فقط برای همان سازمان دیده و ویرایش می‌شود و نمی‌تواند خود را عمومی و منتشرشده اعلام کند.

**ادمین → مدیریت Pro → بازبینی بانک حرکات اصلاحی → دریافت بانک اصلاحی:** برای انتشار هر حرکت، اطلاعات اجرا، عضلات، ناحیه، هدف، نوع، تجهیزات، سطح، وضعیت شروع، احتیاط، منبع HTTPS، نام و صلاحیت بازبین و تاریخ معتبر لازم است. انتشار و ویرایش با revision کنترل و در audit ثبت می‌شود. شناسه‌های عمومی ce/public از شناسه‌های custom مربی جدا هستند؛ حساب مربی نمی‌تواند شناسهٔ آیندهٔ بانک عمومی را رزرو کند. تکرار پاسخ گم‌شده دوباره revision را زیاد نمی‌کند. تصویر و ویدئو اختیاری‌اند؛ رسانهٔ واقعی یا مجوز آن در سند وجود نداشت و تصویر فرضی اضافه نشده است. برچسب‌های NASM توالی اجباری تولید نمی‌کنند.

منبع اولیه: `Behtan_Corrective_Exercise_Bank_Spec.docx`؛ SHA-256: `a2fa3294200acea1499223fe72fbdbb819e89ee4e4d7af9efcbe345ef7b56b05`.

## تعریف شاخص‌های ادمین

- متخصص: یک حساب دارای پروفایل حرفه‌ای کامل، مستقل از تعداد فضای کاری؛ تفکیک رسته براساس رستهٔ فعلی پروفایل است. زمان ثبت از `registered_at` برای پروفایل‌های جدید، سپس درخواست Pro یا اولین عضویت برای رکوردهای قدیمی گرفته می‌شود. تاریخ نامعلوم جعل نمی‌شود؛ رکورد بدون تاریخ فقط در همهٔ زمان‌ها شمرده می‌شود و شمار آن نمایش داده می‌شود. تغییر پروفایل، زمان ثبت اولیه را جابه‌جا نمی‌کند.
- مراجع: یک پروندهٔ واقعی ثبت‌شده؛ نسخه‌های اطلاعات یک پرونده دوباره شمرده نمی‌شوند. یک فرد در دو سازمان دو پرونده دارد. داده‌های sandbox اولیه در این شاخص نیستند؛ پروندهٔ واقعی آرشیوشده جزو سوابق ثبت‌شده است.
- تغذیهٔ خودکار: سند ذخیره‌شدهٔ موتور در `pro_real_plans`؛ اختصاصی: سند nutrition در `pro_authored_plans`. مجموع دقیقاً جمع این دو است. واردکردن پیش‌نویس موتور به تدوین اختصاصی و ذخیرهٔ آن، سند اختصاصی محسوب می‌شود. گزینه‌های یک وعده و روز تمرین/استراحت، برنامهٔ جدا شمرده نمی‌شوند.
- تمرین خودکار: برنامهٔ تأیید و ثبت‌شده در `pro_training_approvals`؛ اختصاصی: سند training در `pro_authored_plans`. پیش‌نویس خودکارِ تأییدنشده شمرده نمی‌شود.
- تحلیل بدن: یک job با state برابر complete، براساس زمان ایجاد آن job؛ خطا و تلاش مجدد همان job سند جدید محسوب نمی‌شود.

بازه بر زمان ثبت هر نوع سند اعمال می‌شود، نه زمان ثبت مراجع آن. هیچ نام، شماره یا اطلاعات سلامت در خروجی آمار نیست. RPC آمار فقط برای مدیر معتبر مجاز است؛ count نمایشی مرورگر منبع آمار نیست.

### نشست SSH سرور ایران

ابتدا روی DB آزمایشی امتحان کنید. سپس بعد از تأیید خودتان روی محیط هدف اجرا کنید. این دستورات توسط این PR به‌صورت خودکار روی production اجرا نمی‌شوند.

```bash
cd /opt/behtan/supabase
(
  set -eu
  umask 077
  behtan_backup=$(mktemp /opt/behtan/migration/pre-pro-ux-XXXXXX.dump)
  docker compose exec -T db pg_dump -U postgres -d postgres -Fc > "$behtan_backup"
  test -s "$behtan_backup"
  docker compose exec -T db pg_restore -l < "$behtan_backup" > /dev/null
  docker compose exec -T db psql -U postgres -d postgres -v ON_ERROR_STOP=1 \
    < /opt/behtan/migration/20261108113719_053_pro_studio_menu_counts.sql
  docker compose exec -T db psql -U postgres -d postgres -v ON_ERROR_STOP=1 \
    < /opt/behtan/migration/20261108113727_054_pro_corrective_bank_metrics.sql
)
```

هر فایل باید COMMIT بدهد. بررسی فهرست بکاپ جای آزمون بازیابی کامل نیست. اگر یکی از فایل‌ها خطا داد، ادامهٔ انتشار متوقف شود؛ فایل موفق را دوباره اجرا نکنید.

## بازگشت و محدودیت تست

این بسته دادهٔ تاریخی را بازنویسی نمی‌کند. برای برگشت کد، داده، برنامه، audit یا رکورد بانک را حذف نکنید. نسخهٔ قدیمی همهٔ جایگزین‌های جدید را نمایش نمی‌دهد؛ برای این سوابق، نسخهٔ سازگار جدید یا fix رو به جلو ترجیح دارد. migrationهای افزایشی را نگه دارید. بازگشت کد، بازگشت دیتابیس نیست.

نتیجهٔ دقیق تست‌های واحد، SQL، PostgreSQL واقعی، مرورگر، PDF و build در PR ثبت می‌شود. داده‌ها و بازبین تست مصنوعی‌اند؛ دادهٔ تست منتشرشده در CI، تأیید علمی ۱۱۷ حرکت واقعی نیست. تست محلی جای شبکهٔ ایران و بررسی production را نمی‌گیرد. نتیجهٔ جست‌وجوی محدود یا نرخ قبولی fixture به‌عنوان نتیجهٔ کاربران واقعی گزارش نمی‌شود.
