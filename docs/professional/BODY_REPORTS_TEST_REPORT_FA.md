# گزارش تست نسخه گزارش بدن

مبنای مخزن: `2b47055b1732ea245090033af725b1de403f3d8a`، main پس از PR 16.

## اجراشده در محیط توسعه

- 321 بررسی SQL روی PGlite: RLS/tenant isolation، نقش و OTP، انقضا و تعلیق فقط‌خواندنی، لغو عضویت، درخواست تکراری، اجاره پردازش، سقف retry، نسخه ورودی، تغییرناپذیری گزارش/تأیید/پیوست و رویداد خطای scan.
- 574 ترکیب مستقل منوی رژیم؛ بدون تغییر موتور/منو/PlanPreview/printPlan.
- 14 قرارداد UI، 17 اعتبارسنجی ورودی و توقف پزشکی، 8 مقایسه schema بازیابی.
- 54 تست API موتور، 54 تست ساخت حساب، 46 تست گزارش بدن/Responses contract/محدودیت HTTP/رضایت/رد ورودی مخرب و cache نتیجه.
- اجرای همان تست‌های سرور در گراف 25 ماژول JS-only برای بررسی rewrite importها و بارگذاری هر سه API بعد از کامپایل.
- 3 سناریوی ایمنی بکاپ: پیکربندی مفقود، عدم نمایش رمز اتصال نامعتبر، رد checksum خراب پیش از اجرای ابزار خارجی.
- 62 تست مرورگر مجموعه اصلی Pro روی دسکتاپ و موبایل پاس شدند. سپس 6 اجرای هدفمند نیز پاس شدند: 4 اجرای جدید لغو دسترسی در مودال تو در تو و پیوست واقعی PDF، به‌علاوه 2 بازاجرای تأیید/بستن گزارش. مجموع پوشش یکتای Pro برابر 66 سناریو در دو اندازه نمایش است.
- 18 تست ادمین در دو اندازه نمایش پاس شده‌اند؛ پاک‌سازی پس از اصلاح قفل مودال دوباره در هر دو اندازه بررسی شده است.
- بیلد B2C، Admin و Pro و typecheck سرور موفق. بیلد Pro با flag فعال نیز جداگانه موفق بود؛ حضور رابط گزارش در artifact فعال و نبود نام متغیرهای secret سرور در آن بررسی شد. هشدار اندازه chunk ادمین همچنان وجود دارد؛ خطای بیلد نیست.
- رگرسیون auth، security، payments، production، admin، onboarding، age، body-scan B2C، medical-safety، meal-progress و diagnostics موفق.
- نمونه PDF با داده مصنوعی تولید و صفحه پیوست فارسی رندر و از نظر خوانایی/RTL بررسی شد.

## اجرا نشده و شرط تست انتشار

- API واقعی OpenAI: کلید یا دسترسی حساب شما در این محیط نداریم؛ پاسخ ارائه‌دهنده در تست‌ها کنترل‌شده است. این تست‌ها ادعای دقت بالینی یا مقایسه واقعی مدل‌ها ندارند.
- اتصال به کاربران یا عکس‌های سلامت واقعی، اعمال Migration روی Supabase زنده، تغییر Vercel یا انتشار انجام نشده.
- PostgreSQL native و pg_dump/pg_restore واقعی در این محیط اجرا نشده‌اند؛ نصب ابزار بومی در محیط محدود ممکن نشد. workflow فعلی CI همان تست‌های native و restore را روی PostgreSQL 17 مصنوعی اجرا می‌کند. موفقیت آن باید روی PR بررسی شود؛ PGlite جای آن را نمی‌گیرد.
- اسکریپت backup روی Supabase واقعی اجرا نشده و هیچ بکاپ Production برای شما ساخته نشده است. checksum/list verification به‌تنهایی اثبات restore نیست.

## نکات اصلاح‌شده هنگام تست

- Escape در مودال تو در تو نباید والد را هم ببندد؛ event propagation متوقف شد.
- dropdown باید در top layer همان dialog باشد، نه پشت backdrop.
- لغو دسترسی باید هر دو مودال را ببندد و scroll lock حتی هنگام unmount تو در تو آزاد شود.
- در حین عملیات، بستن مودال عمداً غیرفعال است؛ تست باید تا پایان عملیات صبر کند.
- برای مرورگر محدود محیط، Chromium 153 جداگانه استفاده شد؛ وابستگی Chromium وارد package پروژه نشده است. timeout مجموعه UI از 20 به 60 ثانیه افزایش یافته تا مسیر چندمرحله‌ای PDF/عکس روی CI کند قطع نشود.
