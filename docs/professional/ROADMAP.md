# Development roadmap — dependency order

This is the implementation order for Production-Ready V1, not an estimate of calendar delivery. Every phase needs runnable artifacts, a test report and staging review before live deployment. Market interviews are optional research, never a development gate.

| Phase / priority | Depends on | Work packages | Acceptance / tests |
|---|---|---|---|
| P1 / P0: sandbox foundation (this branch) | audited main + PRD | tenant tables, multi-role memberships, protected helper functions/RLS, pilot allowlist, generated patient fixtures, explicit assignments, separate Pro build, retry-safe workspace shell, CI/test harness | non-superuser isolation, no self-escalation, revoked membership/assignment, OTP identity, idempotent retries, no B2C entitlement or table changes; browser desktop/mobile flow |
| P2 / P0: patient registry and permissions | P1; policy draft | separate reception + health intake revision tables; phone normalization; duplicate detection scoped to org; qualified practitioner review flow; team management/last-owner transfer; processing consent evidence + patient-controlled progress grants; immutable consent events; organization license model | assistants never select health columns; owners without assignments cannot read clinical data; unverified/revoked/expired credentials denied; cross-tenant FK attacks; duplicate/wrong/shared number; consent revocation; race/stale revision; license expiry |
| P3 / P0: authoritative nutrition service | P2 | extract shared engine with injected catalog/policy; preserve B2C adapter; server input contract and medical eligibility; versioned input/catalog/engine snapshots; tamper/recompute validation, resource limits, supported clinician edit rules | golden B2C output corpus; unit/property tests for targets/macros/portions; hard stops; request context isolation; untrusted output cannot be approved; deterministic replay; timeout/unsupported input |
| P4 / P0: clinical review + immutable publication | P2 + P3 | draft editor with bounded changes, diff/review, concurrency conflict UX, approve exact digest, atomic publish/access/outbox, request deduplication, immutable versions and correction lineage | no update/delete approved content, stale editor rejects, approve-vs-edit race, double publish/retry, license/credential/consent revocation races, medical recheck; complete clinician E2E |
| P5 / P0: invitation, claim + patient source resolver | P4 | hashed expiring invitations; outbox leases/backoff/retry dashboards; SMS worker; verified phone claim + relationship acceptance; separate optional progress consent; source selector before B2C paywall; frozen-plan rendering | failure SMS leaves publication intact; duplicate callback; expired/wrong phone/recycled phone recovery; two practitioners + B2C; no subscription purchase for entitled pro plan; no client regeneration; offline/retry/access expired |
| P6 / P1: tracking + practitioner follow-up | P5 | professional version-scoped meal checkins, patient progress, provider summary with scoped permissions; tablet/mobile access, empty/error/end states, accessible UI | revoke progress access without ending patient plan, no cross-version checkin mixing; optimistic UI rollback/reconnect; accessibility; actual transport E2E |
| P7 / P0 release: production hardening | P1–P6 + clinical/legal/security sign-offs | org billing/license settlement, verified webhooks, quotas/rate limits, observability/alerts, outbox reconciliation, incident playbook, backup/restore, load/concurrency tests, data retention implementation and launch flags | native PG + staging Supabase RLS/JWT tests, OTP/SMS sandbox provider tests, existing B2C suites, payment regressions, load budgets, restore drill; documented go/no-go and controlled rollout |

## Immediate next implementation slice

P2a: define and test clinical `patient_records` / `patient_intake_revisions` separately from reception, introduce exact processing authorization states, implement credential review as a platform-only action, add consent/RLS negative tests **before** exposing a clinical form. P1 fixture rows are disposable and never become real patient records.

## Validation without interview dependency

Build a synthetic scenario matrix: two organizations; owner-only, assistant, assigned/unassigned clinician; patient with B2C and two specialists; normal eligible and every medical hard stop; Persian/Arabic digits; repeated and recycled/wrong numbers; lapsed license; lost network response; stale draft; notification failure; revoked progress consent. Tie each scenario to executable acceptance tests in its phase. Instrument task completion time, draft correction rate, publication failures, invitation claim rate, patient access, checkin return and retention with no health values in analytics. Validate willingness to pay in the controlled commercial pilot, without claiming engineering tests establish product-market fit.
