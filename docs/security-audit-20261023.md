# بررسی کد و امنیت به‌تن

تاریخ: ۲۳ اکتبر ۲۰۲۶ · نسخهٔ مبنا: `main@9c7605c`

## نتیجه

کدهای اضافی حذف نشده‌اند و ساختار اپ، صفحات، موتور تغذیه و مسیرهای اصلی تغییر نکرده‌اند. اصلاح‌های این پچ فقط برای امنیت درخواست‌ها، محدود کردن مصرف سرویس هوش مصنوعی، حفاظت از پاسخ‌ها و فایل‌های محیطی، و به‌روزرسانی وابستگی‌های آسیب‌پذیر است.

این بررسی شامل موجودی ۴۹۲ فایل ثبت‌شده، نمودار وابستگی سه ورودی اپ/ادمین/Pro، وابستگی‌های npm، مسیرهای سرور و Edge، الگوهای دسترسی دیتابیس و تست‌های مربوط بوده است. بررسی سورس و تست محلی جایگزین تست نفوذ روی محیط واقعی نیست. تنظیمات زندهٔ Supabase، کلیدهای Vercel، محدودیت‌های شبکه و تاریخچهٔ کامل Git در این بررسی تأیید نشده‌اند.

## اصلاح‌های انجام‌شده

| مورد | مشکل | اصلاح |
| --- | --- | --- |

| مصرف اسکن بدن | کاربر واردشده می‌توانست درخواست‌های معتبر پشت‌سرهم به Gemini بفرستد | سهمیهٔ دیتابیسی برای هر حساب با شمارهٔ تأییدشده: حداکثر ۵ درخواست در روز با فاصلهٔ حداقل ۱۰ ثانیه |
| دور زدن سهمیه | محدودیت در حافظهٔ یک تابع برای چند اجرای سرور کافی نیست | رزرو اتمیک با UPSERT در دیتابیس؛ جدول برای کاربر و مهمان قابل دستکاری نیست |
| خرابی سرویس سهمیه | خطای سهمیه نباید به فراخوانی بی‌محدودیت مدل منجر شود | در صورت خطا، مدل فراخوانی نمی‌شود؛ اسکن دستی همچنان مسیر جایگزین است |
| پاسخ اسکن بدن | پاسخ دارای اطلاعات شخصی هدر منع کش نداشت | افزودن `Cache-Control: no-store`؛ سقف خروجی مدل ۲۰۴۸ توکن |
| ورودی پرداخت | JSON خراب یا مقادیر null و array به خطای عمومی سرویس می‌رسیدند | پاسخ ۴۰۰ پیش از دسترسی به احراز هویت یا دیتابیس |
| کلیک‌ربایی و دسترسی مرورگر | هدرهای عمومی امنیتی در تنظیمات انتشار نبودند | منع نمایش در iframe، منع تشخیص خودکار نوع فایل، سیاست Referrer و محدودیت میکروفن/موقعیت مکانی؛ دوربین خود سایت مجاز می‌ماند |
| فایل‌های محیطی | فقط بعضی نام‌های `.env` نادیده گرفته می‌شدند | نادیده گرفتن تمام `.env.*` به‌جز فایل نمونه |
| ابزار توسعه | نسخهٔ قفل‌شدهٔ Vite و چند بستهٔ وابسته هشدار امنیتی داشتند | Vite از ۵٫۴٫۲۱ به ۶٫۴٫۴؛ به‌روزرسانی سازگار esbuild، brace-expansion، js-yaml و source-map-js در lockfile |

سهمیه قبل از فراخوانی مدل مصرف می‌شود؛ خطای مدل هم یک تلاش محسوب می‌شود. مبنای روز، `current_date` دیتابیس است، مطابق سهمیهٔ فعلی اسکن غذا. این جدول فقط شناسهٔ کاربر، تاریخ، شمارنده و زمان درخواست را نگه می‌دارد؛ هیچ عکسی ذخیره نمی‌شود. دورهٔ نگهداری شمارنده‌ها فعلاً خودکار حذف نمی‌شود و باید در سیاست نگهداری دادهٔ سرویس لحاظ شود.

اسکن بدن پیش از پرداخت در آنبوردینگ اجرا می‌شود؛ سهمیهٔ آن عمداً اشتراک نمی‌خواهد. سهمیهٔ اسکن غذا و کنترل اشتراک آن تغییری نکرده است. درخواست مستقیم به RPC سهمیه هم فقط سهمیهٔ همان حساب را مصرف می‌کند.

## وابستگی‌ها و هشدارهای باقی‌مانده

| وضعیت npm audit | پیش از پچ | پس از پچ |
| --- | --- | --- |
| همهٔ وابستگی‌ها | ۱۲ هشدار: ۹ بالا، ۳ متوسط | ۷ هشدار: ۵ بالا، ۲ متوسط |
| وابستگی‌های محیط اجرا با `--omit=dev` | — | صفر هشدار ثبت‌شده |

صفر بودن audit به معنی نبود تمام آسیب‌پذیری‌ها نیست. هفت هشدار باقی‌مانده در زنجیرهٔ ابزار توسعهٔ Tailwind هستند: `braces`، `chokidar`، `fast-glob`، `micromatch`، `postcss-nested`، `postcss-selector-parser` و `tailwindcss`. این‌ها هفت مسیر بسته‌اند و الزاماً هفت آسیب‌پذیری مستقل نیستند. ورودی تحت کنترلشان فایل‌ها و الگوهای build/dev است، نه دادهٔ وعده یا پروفایل ارسالی کاربر به سرور.

پیشنهاد خودکار npm برای حذف همهٔ هشدارها ارتقای عمدهٔ Tailwind به نسخهٔ ۴ است. این ارتقا می‌تواند CSS و ظاهر را تغییر دهد و در این پچ انجام نشده است. جایگزین کردن اجباری نسخه‌های ناسازگار با overrides هم انجام نشده. این بدهی باید در یک تغییر مستقل همراه با مقایسهٔ تصویری اپ، ادمین و Pro رفع شود. سرور dev/preview نباید به‌عنوان سرور عمومی محصول استفاده شود.

مرجع نسخهٔ اصلاح‌شدهٔ Vite: [اعلان رسمی امنیتی Vite](https://github.com/vitejs/vite/security/advisories/GHSA-rq7h-c2jc-7f22). نسخهٔ ۶٫۴٫۴ کمترین شاخهٔ اصلاح‌شدهٔ سازگار برای این تغییر بود؛ افزونهٔ فعلی React با آن سازگار است و هر سه build پاس شدند.

همهٔ هفت وابستگی اصلی در کد استفاده می‌شوند؛ بستهٔ اصلی قابل حذف پیدا نشد. از `npm audit fix --force` استفاده نشده است. بعضی ابزارهای داخلی مثل `esbuild` در تست‌ها و `@eslint/js` و `globals` در تنظیمات lint از وابستگیِ غیرمستقیم استفاده می‌کنند؛ بهتر است در تغییر نگهداری بعدی به‌عنوان وابستگی مستقیم توسعه ثبت شوند تا تغییر زنجیرهٔ نصب آن‌ها را نشکند. نصب فعلی و تست‌ها با lockfile حاضر کار می‌کنند.

- فایل‌های `*_CHANGED_FILES.txt` و مانیفست‌های پچ: مستندات انتشارند و نقشی در رفتار اپ ندارند؛ می‌توان بعداً با سیاست نگهداری مشخص آرشیوشان کرد.

Migrationها، schema، seedها، تصاویر تمرین، فونت‌ها و فایل‌های تست صرفاً به دلیل نداشتن import حذف‌پذیر نیستند. نمودار import معیار مناسبی برای حذف آن‌ها نیست.

## امنیت مسیرهای اصلی

- پرداخت: قیمت و تسویهٔ اشتراک از مسیر سروری و دیتابیس انجام می‌شود؛ callback عمومی اطلاعات سفارش کاربر را برنمی‌گرداند. تست‌های جعل callback، کنترل مالکیت و پرداخت پاس شدند.
- ادمین و Pro: تست‌های فعلی دسترسی نقش‌ها، مرز سازمان‌ها و پرونده‌ها و عملیات سروری اجرا شدند و پاس شدند. ایراد تأییدشدهٔ تازه‌ای برای دور زدن دسترسی در این بررسی پیدا نشد؛ این ادعا تضمین نبود ایراد نیست.
- تصویر و هوش مصنوعی: کلید مدل در کلاینت قرار ندارد؛ اعتبارسنجی نوع تصویر و خروجی وجود دارد؛ عکس بدن در مسیر بررسی‌شده پایدار ذخیره نمی‌شود.
- نمایش HTML: ورودی‌های گزارش‌های چاپی escape می‌شوند. `dangerouslySetInnerHTML` نماد اعتماد از متن ثابت داخل سورس استفاده می‌کند و ورودی کاربر نیست؛ حذف بی‌دلیل انجام نشد.
- کلیدها: در محتوای فعلی فایل‌های ثبت‌شده، تطبیق تأییدشده‌ای برای private key، توکن سرویس‌های شناخته‌شده یا JWT با نقش service_role پیدا نشد. این اسکن مبتنی بر الگوست؛ تاریخچه و کلیدهای محیط واقعی بررسی نشده‌اند.

سیاست کامل CSP برای تمام منابع خارجی هنوز تنظیم نشده است. هدر این پچ فقط `frame-ancestors` را محدود می‌کند و Turnstile، نماد اعتماد، فونت و عکس را مسدود نمی‌کند. محدود کردن script-src/connect-src باید جداگانه با آزمایش واقعی ورود و پرداخت انجام شود.

## بررسی‌ها و محدودیت‌ها

۳۶ فرمان بررسی و تست پاس شدند، از جمله:

- تست جدید خواندن chunked، شمارش بایت UTF-8، لغو stream، سقف SMS/پرداخت/اسکن، ورودی خراب پرداخت، جلوگیری از فراخوانی مدل هنگام رد یا خرابی سهمیه و پاسخ بدون کش.
- تست SQL واقعی با PGlite برای سهمیه: اعمال دوبارهٔ Migration، مهمان، حساب تأییدنشده، عدم دسترسی مستقیم به جدول، فاصلهٔ زمانی، سقف روزانه، جداسازی دو کاربر و شروع روز بعد. تست فشار هم‌زمان روی دیتابیس زنده انجام نشده است.
- تست‌های production شامل auth، security و payments؛ Pro و ادمین؛ lifecycle آنبوردینگ؛ حریم خصوصی تصویر؛ ایمنی پزشکی؛ ثبت وعده و روند؛ موتور تغذیه و پروتئین؛ آلرژی، جایگزینی و منو؛ مسیریابی، اشتراک، تجربهٔ وعده و کاراکتر.
- build اپ، ادمین و Pro؛ نصب وابستگی‌ها و کنترل درخت npm بدون ناسازگاری peer.

lint کامل **پاس نیست**: ۳۲ خطا و ۳۷ هشدار دارد. مقایسه با نسخهٔ مبنا نشان داد همه از قبل وجود داشته‌اند و این پچ مورد تازه‌ای اضافه نکرده است. نمونه‌ها: نام تابع معمولی `useFallback` در renderer که قانون Hook به آن ایراد می‌گیرد، `any` در تست‌های مرورگر و هشدار وابستگی بعضی effectها. برای رعایت درخواستِ عدم تغییر رفتار، این موارد خودکار اصلاح نشده‌اند؛ به‌خصوص افزودن بی‌بررسی وابستگی effect ممکن است حلقهٔ رندر بسازد.

تست‌های مرورگر Playwright و دیتابیس native در این نوبت محلی اجرا نشده‌اند؛ باید نتیجهٔ CI شاخه بررسی شود. انتشار و تغییر محیط زنده انجام نشده است.

## اعمال پچ

۱. روی main به‌روز یک شاخهٔ جدید بساز. پچ مربوط به `9c7605c` است؛ اگر `git apply --check` خطا داد، ادامه نده و از `--reject` استفاده نکن.

```powershell
cd E:\Behtan-Final
git switch main
git pull --ff-only
git switch -c fix/security-hardening
$patch = "$env:USERPROFILE\Downloads\behtan-security-hardening.patch"
git apply --check $patch
git apply $patch
npm ci
npm run test:security:hardening
npm run test:production
npm run build
npm run build:admin
npm run build:pro
```

۲. اگر بررسی‌ها پاس شدند، فقط فایل‌های پچ را commit و push کن:

```powershell
git add .gitignore .github/workflows/pro-foundation.yml package.json package-lock.json vercel.json docs/security-audit-20261023.md scripts/security-body-limits.test.mjs supabase/functions/_shared/boundedBody.ts supabase/functions/body-scan/index.ts supabase/functions/payments/core.ts supabase/functions/send-sms/index.ts supabase/migrations/20261023_034_body_scan_quota.sql
git commit -m "Harden edge request limits and body scan quota"
git push -u origin fix/security-hardening
```

۳. برای این شاخه PR بساز و صبر کن CI کامل پاس شود. این تغییر پس از ادغام روی Vercel build می‌شود؛ Edge Functionها جداگانه منتشر می‌شوند.

۴. **قبل از انتشار نسخهٔ جدید body-scan**، محتوای کامل فایل `supabase/migrations/20261023_034_body_scan_quota.sql` را در SQL Editor همان پروژهٔ Supabase اجرا کن. این Migration افزایشی است و با نسخهٔ قبلی اپ سازگار است. Migrationهای قبلی را دوباره اجرا نکن. برای نصب روی محیط جدید، ترتیب Migrationهای قبلی باید رعایت شده باشد.

۵. از همان مخزنِ دارای پچ، سه تابع را در همان پروژهٔ متصل Supabase منتشر کن. اگر CLI به پروژه متصل نیست، ابتدا `supabase link --project-ref YOUR_PROJECT_REF` را با شناسهٔ واقعی پروژه اجرا کن و پیش از انتشار نام پروژه را بررسی کن.

```powershell
supabase functions deploy body-scan
supabase functions deploy payments --no-verify-jwt
supabase functions deploy send-sms --no-verify-jwt
```

بررسی JWT برای body-scan فعال می‌ماند. برای payments، callback عمومی بانکی نیاز به مسیر بدون JWT دارد و تأیید سفارش داخل تابع انجام می‌شود. برای send-sms، امضای webhook احراز اصالت را انجام می‌دهد؛ این دو فلگ معماری فعلی را حفظ می‌کنند و امضای webhook حذف نشده است. کلید یا Secret تازه‌ای لازم نیست.

۶. ورود با OTP، اسکن بدن در آنبوردینگ و یک پرداخت sandbox را بررسی کن؛ ارسال SMS، نتیجهٔ اسکن و بازگشت پرداخت باید کار کنند. اسکن دستی و ثبت غذا را هم مرور کن. سهمیهٔ اسکن را با حساب آزمایشی تست کن، نه با تغییر شمارندهٔ حساب کاربران واقعی.

برای بازگشت، کد را با revert همان commit و انتشار نسخهٔ قبلی تابع برگردان. Migration سهمیه را حذف نکن؛ جدول افزایشی و بی‌استفاده در نسخهٔ قبلی اختلالی ایجاد نمی‌کند.
